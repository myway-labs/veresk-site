# План адаптации и типографики (v2) — выполнено

> Все задачи закрыты. Документ фиксирует принятые решения и выполненную работу.

## 0. Контракт (принятые решения)

- ✅ **0.1. Единая система `rem`.** Шрифты, отступы, физические размеры блоков и `--radius` — в `rem`. В `px` остаётся только перечисленное в 0.4.
- ✅ **0.2. Reflow снизу / Zoom сверху.** `≤1280` — reflow через `@media (px)`; база `1281–1499` — масштаб `1×`; `≥1500` — ×1.08, `≥1850` — ×1.3, исключительно через `html { font-size }`. `transform: scale()` для layout запрещён.
- ✅ **0.3. `clamp()` только для масштабных значений ≤1280.** Задокументированные исключения: H1 в полосе 1024–1499 (`4.7cqw`, пол `1.7rem`), `geo-map height`, иерархия заголовков 601–1399.
- ✅ **0.4. Что остаётся в `px`:** бордюры/хайрлайны `1px`, брейкпоинты `@media`, `vh`/`vw`, `ch`.
- ✅ **0.5. a11y корня.** `html { font-size: calc(100% * k) }` — от пользовательского дефолта, не фиксированный `px`.
- ✅ **0.6. Один уровень флюида.** Либо корень, либо `clamp` — не оба на одном свойстве.
- ✅ **0.7. Анимации.** Координаты — в `rem` или от фактической геометрии (`getBoundingClientRect`), без хардкода под конкретную ширину.
- ✅ **0.8. Токены-роли.** 7 ролей (`--fs-h1 … --fs-h4`, `--fs-body`, `--fs-small`, `--fs-label`) в `rem`; одна роль = один класс.

## 2. Фирменная логика скруглений (инвариант — не ломать)

Объекты встык читаются как единый блок: скругляются только **внешние** углы (на границе с фоном), внутренние стыки прямые. При перекомпоновке углы сначала обнуляются, затем назначаются заново.

| Компонент | Поведение углов |
|---|---|
| `.pest-card` / `.pest-grid` | десктоп 6×1 → планшет 3×2 (4 внешних угла) → моб. 3 колонки; обнуление в каждом тире |
| `.price-card` / `.prices-grid` | 3×1, только внешние углы; логика снимается ≤1024 |
| `.v2-prices` / `.v2-calc` | пара карточек, внешние углы только ≥1025 |
| `.why-we-step` / `.why-we-mark` | слитное поле; заливка-маркер зеркалит нижний правый угол |
| `.why-we-card` | 2×2 → 1×4 (верх первой / низ последней) |
| `.why-we-note-*` | в ряд: `12px 0 0 12px` + `0 0.75rem 0.75rem 0` + скос на tg → в колонку: текст `12px 12px 0 0`, монолит `0 0 12px 12px` |
| `.b2b-tag` / `.b2b-tags` | 2×3 (4 внешних угла) → в колонку |
| `.cta-deal` / `.cta-discount` | слитная плашка; бейдж зеркалит угол через negative-margin |
| `.image-container-block` | асимметричное скругление героя |
| `.review-card` / `.reviews-track` | внешние края ленты; JS-классы `.is-edge-start/end` |
| `.footer-grid` | скругления нет |

Инварианты:
1. Сначала обнулить углы, потом назначить внешние.
2. Внешний угол — на границе с фоном; внутренние стыки прямые.
3. При смене числа колонок пересчитать угловые элементы.
4. Слитные поля: скругление — на контейнере, бейдж зеркалит угол.
5. Где логика на negative-margin бейджа — не прятать родителя `overflow: hidden`.
6. Единый источник — `--radius-*`; `--radius-*` в `rem`, бордюр `1px`.

## 3. Правила

1. Рассуждаем по коду, без браузерных инструментов и скриншотов.
2. `1440` — пиксель-в-пиксель; менять только по явной просьбе.
3. Не действовать сверх задания.
4. Баг ≠ кэш: hard-reload перед проверкой.
5. Инвариант скруглений — не ломать.
6. Комментарии в коде — на русском, лаконично.
7. Перед фазой — сверка с планом, после — регресс.
